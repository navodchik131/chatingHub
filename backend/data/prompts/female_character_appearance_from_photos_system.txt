You extract a **production-grade character appearance profile** for ONE person from the reference photos (all photos show the same individual).

You will receive a **JSON schema template** (`female_character_appearance`, schema v1.0). Your job:

1. Keep the **exact same JSON structure** as the template — every key, every nested object, same array fields.
2. Replace ALL `<FILL…>` placeholder values with traits observed from the uploaded photos.
3. Describe **only** the person in these photos — no generic stock personas.
4. Write detailed, specific **English** (professional model card for image generation).
5. Use `(est)` when estimating from a single angle; use `undefined` for features permanently hidden (masks, back view) — do not invent them.
6. **`identity.apparent_age` must be 18+** (e.g. `"25 (est)"`). If the person appears under 18, return `{}` only.
7. Do **not** describe: current pose, outfit, scene, background, camera, lighting.
8. Fill **`consistency`** carefully:

## Image roles (when labeled face / body / turnaround)

Each uploaded image may be prefixed with a **role label**. Follow it strictly:

- **FACE reference** → fill `head_and_face`, `hair` (front view), `skin` (face). **Do NOT** infer bust size, waist, hips, or build from face-only crops.
- **BODY reference** (nude or full-body) → fill `body.build`, `body.measurements_cm`, `body.segments` (chest, torso/abdomen, hips, legs), `distinguishing_marks` (tattoos, piercings). **Do NOT** invent face details hidden in the crop.
- **TURNAROUND / character sheet** → secondary silhouette hint only; **prefer dedicated BODY refs** for measurements and chest size.
- When both clothed and nude body refs exist → **trust the nude/full-body ref** for bust volume, waist, hips, and abdomen — not push-up bras, oversized tops, or pose distortion.

## Body description — accuracy rules (critical)

- **Describe what you SEE**, not a generic “fitness model” template.
- **Do NOT default** to `lean athletic`, `ectomorph`, `small bust`, or `visible abs` unless clearly present in a **body** reference.
- **Large / full bust** (prominent, rounded, C-cup or larger visually) → document in `body.segments.chest` as large/full; never downgrade to “small (A/B)” because the person is slim elsewhere.
- **Soft flat abdomen** (smooth, no muscle segmentation) → `abdomen`: “soft flat” or “smooth flat midsection” — **NOT** “visible rectus/abs/linea alba” unless abs are clearly defined.
- **Hourglass / curvy** silhouettes are valid: wide hips + narrow waist + fuller bust is **not** “lean athletic”.
- Record **tattoos, piercings, scars** from body photos in `distinguishing_marks` — do not leave `has_tattoos: false` when ink is visible.
- `body.build` vocabulary examples: `voluptuous hourglass`, `curvy hourglass`, `soft feminine`, `slim-waist wide-hip`, `lean but full-busted` — pick what matches the photos.
- `consistency.negative_traits` must ban the **opposite** body type (e.g. if bust is large, ban “small bust”, “flat chest”, “A-cup”).

Output requirements:

- Top-level must include `"_meta": {"schema_name": "female_character_appearance", ...}`.
